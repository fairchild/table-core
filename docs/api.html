API reference

Everything the package exports. Anything not listed here is internal and may change in any release.

ServerRowsStore<Row>

The server-side row model. Create one per table, connect it to your UI with subscribe and getSnapshot, and drive it with its commands. The commands are bound functions, so they can be passed around as they are.

new ServerRowsStore<Row>(config: ServerRowsConfig<Row>)
subscribe(listener: () => void): () => void
Call listener whenever the snapshot changes. Returns the unsubscribe function.
getSnapshot(): ServerRowsSnapshot<Row>
The current snapshot. The same object until something changes.
start(): void
Begin fetching, when the table appears. Starts a visit. Until the first start(), the snapshot reports fetching: its rows are coming.
stop(): void
Abort everything in flight, when the table goes away, so fetching is false. The cache is kept, so a later start() shows cached rows at once.
update(config: ServerRowsConfig<Row>): void
New options, all of them: an option left out goes back to its default, except now, which keeps the store's clock. Fetchers are always replaced. A new view, page size or mode starts a visit on its own cache entry. Calling it with an unchanged view is cheap and changes nothing on screen.
loadMore(): void
Load-more mode: fetch the next page, or ask again for a next page that failed. Does nothing when there is no next page.
setPage(page: number): void
Pages mode: show page page, counted from 0. Starts a visit.
retry(): void
Ask again for what failed: the failed page, or, after a failed refresh, everything stale on screen.
reload(): void
After a change on the server: mark every cached page stale and fetch what's on screen again. The rows stay on screen meanwhile. If the refresh fails, they're shown as saved data.

ServerRowsConfig<Row>

OptionDefaultMeaning
viewrequiredA TableView: what the server sorts by.
fetchRowsrequired(request: ServerRowsRequest) => Promise<ServerRowsResponse<Row>>. See your server's contract.
fetchCountnone(request: ServerCountRequest) => Promise<number>. Resolves with the count as a plain number, not an object. The exact count, asked for at most once per visit: when a page reports { atLeast } without settling the count; again when a count it gave is redone (reload, revalidation, a count older than staleAfter); when a page fetched during that can't settle it; and when an empty page in pages mode finds the count too high. A count that pages settle themselves isn't asked for. The rows win here too, but only rows held with no gap from the first row, fetched since the last reload and newer than staleAfter: a count below them is read as { atLeast } of the furthest rows held. Rows past a gap, as after a deep link, don't overrule a count.
pageSize50Rows per request. Part of a page's identity: a new size starts over.
mode'load-more''load-more' appends pages, chaining cursors. 'pages' shows one page at a time, by offset.
staleAfter30000Milliseconds. Cached pages, and a count, older than this are fetched again when they come back on screen.
maxViews20How many views keep their pages, counting the one on screen. A view here is a sort, filter and page size. Past this, the view shown longest ago leaves the cache and is fetched again when it comes back. Infinity keeps every view.
nowDate.nowThe clock, for tests.

ServerRowsRequest

view: TableView
The view to fetch.
offset: number
Rows to skip. Always set.
cursor?: string
Load-more mode: the previous page's nextCursor.
limit: number
The page size.
signal: AbortSignal
Aborted when the request goes out of date or the store stops.

ServerRowsResponse<Row>

rows: Row[]
The page, in the view's order. Without a cursor, fewer than limit rows means this is the last page, unless this response's total says there are more.
total?: Total
An exact count, or { atLeast } while it is expensive to compute. The rows win over a number below them: a total less than the rows through this page is read as { atLeast } of them, so the rest of the list stays reachable.
nextCursor?: string | null
The next page's cursor; null on the last page, which settles the count at the rows through it unless this page's { atLeast } is above them. Omit for offset paging.

ServerCountRequest

view: TableView
The view to count.
signal: AbortSignal
Aborted when the count is no longer wanted.

ServerRowsSnapshot<Row>

rows: readonly Row[]
The rows to show: this view's, or, while it loads, the previous view's (see state.rows). The same array until they change.
state: TableState
See TableState.
total?: Total
The best count known, consistent with the rows.
paging
{ kind: 'load-more'; hasMore: boolean } or { kind: 'pages'; page: number; pageCount: number }.

pageKey(view, pageSize): string

The cache identity of a page: everything that changes which rows a page holds. Useful if you keep your own cache alongside the store's.

TableState

interface TableState {
  rows?: 'current' | 'previous' | 'none';
  fetching?: boolean;
  since?: Date;
  failure?: {
    message?: string;
    retry: () => void;
    scope: 'load' | 'refresh' | 'more';
  };
}

Independent facts. The store always sets rows and fetching: settled rows of the current view are { rows: 'current', fetching: false, since }. The fields are optional for a table that has its own rows, where {} means the same. See reading the state.

TableView

type TableView = {
  sort: SortItem[]; // length 0 or 1 in version 1
  filter?: TableFilter;
};

Everything a saved view stores. Later versions add optional keys. Until 1.0, a minor version may rename or remove one; the CHANGELOG says what to change.

SortItem

type SortItem = {
  columnId: string;
  direction: SortDirection;
};

SortDirection

// The same words as aria-sort.
type SortDirection = 'ascending' | 'descending';

Total

type Total = number | { atLeast: number };

A count, or a lower bound while the exact figure is computed (“50 of 1,000+”).

TableFilter

type TableFilter = {
  readonly [key: string]: FilterValue | undefined;
};

Your own keys and values: a search term, a status. The store doesn't read them; it sends them to your fetchers in view and keys its cache by them, so a new filter starts at the first page. Put a search term here, not in a closure in fetchRows.

FilterValue

type FilterValue =
  | string | number | boolean | null
  | readonly (string | number | boolean | null)[];

Plain JSON, so a view can be saved and put in a URL.

Selection

type Selection =
  | { kind: 'ids'; ids: ReadonlySet<string> }
  | { kind: 'all-matching'; except: ReadonlySet<string> };

These rows, or every row matching the view except these. See selection.

isSelected(selection, id): boolean

Whether the row is selected.

setSelected(selection, ids, on): Selection

Tick (on = true) or untick rows. In an all-matching selection, unticking adds to except and ticking takes out of it. Returns a new selection.

removeFromSelection(selection, deleted): Selection

The selection after rows were deleted on the server: they leave it, and leave except too, because the server's new total no longer counts them. Returns the same object when nothing changes.

selectionCount(selection, total, shown): Total

How many rows are selected. An all-matching selection counts against total, or against shown when there is no total; a lower bound stays a lower bound.
